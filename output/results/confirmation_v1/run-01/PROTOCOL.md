# muKG 确认实验 v1

M11-GPU 承担主判断，M10-GPU 是事先声明的省时备选。数据为官方 FB15k-237，使用历史初始化的 TransE 250 维 L1、logistic_adv、margin 7、adv 2、Adam 0.0005 和每条 150 个负样本。训练使用同一张 RTX 3070 和 10 个 CPU 线程。A 保留历史 CPU 路径。M00 固定 75 头与 75 尾，M10 和 M11 每条正样本随机选择一端，M11 对该行去重。M 系列过滤原样本与训练集真三元组，最多 64 轮重试。

## 执行与验收

1. 用实际 CUDA 运行历史对照和确认专项测试。预检使用独立种子 550，尝试共同批大小 5000、2500、1000，记录实际 OOM 与 90% reserved 门槛。完整轮与验证为卡片估时提供依据，另加 30% 排期余量。
2. 封存协议、输入身份、环境、源码、核验材料及 204 张任务卡。每个阶段使用 Williams 顺序按种子平衡组的位置。S 为 521–532 共 72 卡，T 为 541–546 共 36 卡，Q/E 为 501–512，各 48 卡。
3. S 测量完整训练轮，T 分开测量各阶段和完整/短批。每卡完整预热 1 轮，随后测 5 轮。Q 固定 1000 轮，每 10 轮完整验证。用验证最高双向 MRR 选模，并列取最早轮次。
4. 校验全部 Q 的排名、配对身份、最优及末轮 checkpoint，固定 S/T/Q 成果及选模清单，再核验官方测试 SHA-256。E 只使用选定最佳 checkpoint。验证过滤 train＋valid，测试过滤 train＋valid＋test，使用平均并列排名。
5. 从原始排名与耗时独立复算，核验归档哈希。质量比较用 12 对 MRR 比值的几何均值及双侧 95% 对数 t 区间。M11/A 下界 ≥0.95 支持门槛，上界 <0.95 判为未达，其他为证据未定。速度使用每卡五轮均值的耗时比，A/M11-GPU 下界 >1 支持加速，另报两个匹配 CPU/GPU 比值。质量和整体速度都获得区间支持时才报告联合达成。

历史旧 Q 阶段已使用 FB15k-237 官方测试集。缺失或终止的任务按卡记录，固定设计的主要判断须等完整配对。

## 命令

从本 worktree 调用 `python -B -m src.py.experiments.formal_v1 confirmation`，后接下列子命令。默认根目录为 `output/results/confirmation_v1/`，每个检查或运行目录使用新名称。

- `check --output <checks>`
- `preflight --checks <checks> --output <preflight>`
- `freeze --preflight <preflight> --output <run>`
- `run-queue --run <run> [--phase S|T|Q|E] [--resume]`
- `run-task --run <run> --task <任务编号> [--resume]`
- `status --run <run>`
- `stop --run <run>`
- `analyze --run <run> --output <报告目录>`

独立 worker 由队列控制器启动。GPU 占用时等待。明确的 GPU 干扰允许原配置从头重试一次。中断后用 `--resume` 从任务起点恢复，全部尝试保留。科学错误停止派发，变更实现或科学配置须重新冻结并重新取得受影响的同期对照。

按阶段或编号派发时，队列仍按冻结顺序执行。批次哈希在计时区间之外生成。预检分别实测完整预热轮、S 轮、T 轮和质量路径的完整验证。所有文件身份沿用历史正式实验固定的官方划分。分析目录与运行目录分开，全部 204 项核验后会复制完整运行目录并校验同机存档。

T 的采样计时涵盖 GPU 采样器内部的正样本输入复制，正样本传输列记录供模型前向使用的独立复制。S 的显式计时同步位于轮边界，M 采样器本身仍需检查拒绝与重试条件。负样本已经在 GPU 的路径中，负样本传输列记录设备保持不变的调用及阶段边界开销。
