# muKG 负采样优化：阶段性研究故事

日期：2026-11-06。状态：用户审阅后的研究故事存档。本文记录已有证据与尚待验证的问题，不构成正式实验结论。

## 1. 从训练效率问题出发

本研究围绕 muKG 中的负样本准备开销，探索 GPU 张量化实现，通过明确采样规则、统一训练评估和设置匹配对照，研究训练效率与预测质量的取舍。当前聚焦 TransE 与 FB15k-237。

CPU 路径承担候选生成、三元组构造、过滤、重试与张量准备。早期性能记录提示这部分值得研究，但旧计时存在区域重叠：Collate 已包含负采样和张量构造，汇总时又将三者相加。因此旧 46.63%、35.7%、10.74% 不能解释为互不重叠的训练时间占比，也不作为新方案的精确瓶颈证据。

当前问题是：在明确采样规则、统一训练评估后，GPU 采样路径能否缩短训练时间，其预测质量代价是多少？早期关于批次波动和多卡等待的设想保留为探索背景，不承担本轮多卡收益证明。

## 2. 成本模型与 CBP 的探索

项目曾尝试预测采样成本，再通过调整批次组织改善效率，路线从实体度数假设转向候选池相关特征，完成成本表、排序和打包接口及相关实验记录。

后续审计发现，相关材料不足以证明真实训练中对未见批次的预测能力；现有 FFDPacker 对同一有序输入等价于顺序切块；部分运行差异受预热、短 batch 和统计口径影响。因此保留该路线为探索记录，不再表述为已验证的成本预测或负载均衡贡献，也不将这一局部结论推广为所有成本调度无效。

继续该路线需要较大补充。当前将核心工作收敛到 GPU 采样的效率与质量验证。GPU 原型早于后来的审计开展，不能写成“审计否定 CBP 后才开始 GPU 研究”。

## 3. GPU 原型与旧运行时证据

GPU 原型使用张量操作批量生成候选、过滤和补充候选，并接入训练。它采用仅尾替换和 batch 正样本尾实体集合过滤，没有按完整三元组检查训练集碰撞。这同时改变了执行设备、方向和过滤规则，既可能拒绝有效候选，也不能完整排除训练集真三元组。

C1-R1 改进了测量：六个配对种子、独立进程、吞吐和 trace 分离、原始纳秒记录、短 batch 标识、环境与代码溯源。

**C1-R1 在旧 SimpleTransE 和指定采样协议下，记录约 6.01 倍端到端 epoch 加速，95% 区间 5.94—6.08。该比较同时改变采样规则与设备，未证明质量保持，不能视为纯设备收益，也不替代新 A/B/C 结果。**

其模型为 400 维 L2 SimpleTransE；CPU 是 R1 脚本参考函数，不等同于 fdfd880；GPU 是仅尾加 batch 尾集合过滤；训练集另留出 5000 条，仅进行短时运行测量。函数名含 original 不证明作者原版身份。

## 4. 质量验证暴露的缺口

早期语义对齐报告已注明排名评估错误，却从两轮 loss 下降推导质量保持或更快收敛。这些推导撤回：不同采样分布下的 loss 不替代链接预测质量。

C1-Q1 在官方划分开展质量检查，但仅完成六个配对中的 seed 42，未满足旧收敛要求，随后被用户中止。它提示旧 GPU 质量风险，不支持总体非劣效判断。

近期诊断进一步展示头尾差异。各组最佳验证 checkpoint 为：

| 旧诊断组别 | 最佳 epoch | 总体 MRR | 头 MRR | 尾 MRR |
|---|---:|---:|---:|---:|
| 历史 CPU | 80 | 0.28907 | 0.18945 | 0.38870 |
| GPU 均衡 | 100 | 0.26135 | 0.17518 | 0.34752 |
| GPU 仅尾 | 100 | 0.27489 | 0.15192 | 0.39787 |

这是已有 seed 7、100 epoch 的验证结果，并非新 A/B/C。最佳轮数不同。仅尾组头较低、尾略高；均衡组相对仅尾改善头指标，但尾及总体较低，不能称为全面更优。GPU 最佳值在上限，最终质量不确定。仅尾也不意味着头实体完全不参与学习。

75+75 是方向明确、便于构建共同 CPU/GPU 对照的待验证选择，不是诊断选出的质量赢家。

## 5. 新 A/B/C 设计

| 组别 | 定义 | 问题 |
|---|---|---|
| A | 历史 CPU 算法 | 最终方案相对历史基线的整体得失 |
| B | 新均衡规则在 CPU 上采样 | 新规则及 CPU 实现的变化 |
| C | 与 B 相同规则在 GPU 上采样 | 相同规则下设备与传输变化 |

三组模型都在 GPU 训练。B 是新正式对照，其完整证据尚待获取。B/C 每条正样本 75 头+75 尾，有放回，按完整三元组过滤训练集真三元组，最多 64 轮、失败不补真样本。A 保留历史行为。A/B 不能隔离每条规则贡献；B/C 不是纯 kernel 比较。

后续问题为：C 相对 A 能否加速且将总体 MRR 下降控制在 5% 内？A/B、B/C 能怎样解释变化？头尾指标、曲线和阶段计时揭示哪些取舍？不因此新增敏感性或扩展任务。

## 6. 成果定位与开放结论

已有成果是 GPU 原型、受协议限制的运行时证据、质量诊断、审计及可追溯材料。新三组设计已明确，完整验证仍待完成。未来可能加速且达标，也可能质量损失、没有加速或区间不确定；按预设规则解释，不追加有利种子。

整体加速不自动证明 GPU 设备贡献，点估计与区间支持分开表述，固定轮数不等于充分收敛。负结果可成为结论，但不能替代缺失任务。结论限于所测模型、数据、硬件与配置，不预设普遍加速、质量保持或算法新颖性。
